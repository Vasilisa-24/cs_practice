Рабочая папка - обычная папка на компьютере, где лежат файлы проекта. Git видит изменения в файлах рабочей папки, но не фиксирует их автоматически. Чтобы изменения попали в историю проекта, их нужно сначала добавить в индекс, а потом сделать коммит.
Индекс — это «черновик коммита»: промежуточная зона, куда явно добавляются файлы командой git add, при их подготовке к фиксации.
Коммит — это фиксация состояния проекта на конкретный момент времени: снимок всех файлов, которые на тот момент были в индексе, плюс метаданные (автор, дата, сообщение-комментарий). Каждый коммит получает уникальный идентификатор (хэш).

Git — это система контроля версий (программа), которая работает локально на компьютере. Она хранит историю изменений файлов, позволяет делать коммиты, переключаться между ветками, откатываться к прошлым версиям и т. д.
GitHub — это веб‑сервис (сайт + инфраструктура), который использует Git. На GitHub хранят удалённые копии репозиториев, делают пулл‑реквесты, ведут обсуждения, настраивают CI/CD и т. п. 
Git — инструмент, GitHub — площадка, где этим инструментом удобно пользоваться в команде.

git diff — сравнивает рабочую директорию (то, что сейчас на диске, последние правки) с индексом (тем, что уже добавилocь через git add).
То есть изменения, которые ещё не подготовлены к коммиту.

git diff --staged (это то же самое, что git diff --cached) — сравнивает индекс (то, что готово к коммиту) с последним коммитом (HEAD).
То есть ровно то, что попадёт в следующий коммит, если сейчас сделать git commit.

git status
Показывает текущее состояние репозитория: какие файлы изменены, какие подготовлены к коммиту, какие ещё не отслеживаются Git.
Можно увидеть в выводе:
Changes to be committed — файлы в индексе (то, что уже сделано через git add и попадёт в следующий коммит).
Changes not staged for commit — изменённые файлы, которые ещё не добавлены в индекс.
Untracked files — новые файлы, о которых Git вообще не знает (их надо сначала добавить через git add).

git diff
Сравнивает рабочую директорию (текущие правки на диске) с индексом (тем, что уже добавлен через git add).
То есть показывает изменения, которые ещё не подготовлены к коммиту.

git diff --staged (он же git diff --cached)
Сравнивает индекс (то, что подготовлено к коммиту) с последним коммитом (HEAD).
То есть показывает ровно то, что будет зафиксировано в следующем коммите, если сейчас сделать git commit.

Ветка — это указатель на конкретный коммит (версию проекта), это линия истории изменений.
Ветки не копируют файлы проекта: они просто «смотрят» на какой‑то коммит и дальше наращивают свою цепочку коммитов.
Самая частая основная ветка — main. В ней обычно держат стабильную версию кода.
Для каждой задачи (новая функция, исправление бага) создают отдельную ветку.
При commit в текущей ветке создаётся новый коммит со всеми изменениями, которые были в индексе, указатель ветки сдвигается на этот новый коммит, то есть ветка теперь «смотрит» на последнюю версию, другие ветки не меняются: у каждой свой указатель, своя история.
Слияние — это объединение истории из одной ветки в другую. Делается командой git merge <имя-ветки>. При этом ты должен быть в той ветке, в которую хочешь влить изменения.
