Рабочая папка - обычная папка на компьютере, где лежат файлы проекта. Git видит изменения в файлах рабочей папки, но не фиксирует их автоматически. Чтобы изменения попали в историю проекта, их нужно сначала добавить в индекс, а потом сделать коммит.
Индекс — это «черновик коммита»: промежуточная зона, куда явно добавляются файлы командой git add, при их подготовке к фиксации.
Коммит — это фиксация состояния проекта на конкретный момент времени: снимок всех файлов, которые на тот момент были в индексе, плюс метаданные (автор, дата, сообщение-комментарий). Каждый коммит получает уникальный идентификатор (хэш).

Git — это система контроля версий (программа), которая работает локально на компьютере. Она хранит историю изменений файлов, позволяет делать коммиты, переключаться между ветками, откатываться к прошлым версиям и т. д.
GitHub — это веб‑сервис (сайт + инфраструктура), который использует Git. На GitHub хранят удалённые копии репозиториев, делают пулл‑реквесты, ведут обсуждения, настраивают CI/CD и т. п. 
Git — инструмент, GitHub — площадка, где этим инструментом удобно пользоваться в команде.

git diff — сравнивает рабочую директорию (то, что сейчас на диске, последние правки) с индексом (тем, что уже добавилocь через git add).
То есть изменения, которые ещё не подготовлены к коммиту.

git diff --staged (это то же самое, что git diff --cached) — сравнивает индекс (то, что готово к коммиту) с последним коммитом (HEAD).
То есть ровно то, что попадёт в следующий коммит, если сейчас сделать git commit.
