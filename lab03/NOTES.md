git diff - Основная задача — показать различия (дифф) между двумя состояниями проекта. Показывает конкретные строки кода, которые были добавлены, удалены или изменены.
git show - Основная задача — детально показать объект Git (коммит, тег, дерево файлов или содержимое большого двоичного объекта) в читаемом виде. Показывает: Для коммита — метаданные (автор, дата, сообщение) и дифф (изменения по сравнению с предыдущим коммитом).

Базовая команда git restore без дополнительных флагов по умолчанию берёт содержимое файла из индекса (области подготовленных к коммиту файлов) и перезаписывает им файл в вашей рабочей директории. То есть она отменяет локальные правки, которые ещё не были добавлены в индекс. 
Флаг --source=... позволяет явно указать, откуда брать исходную версию файла. Вместо индекса можно взять версию из конкретного коммита, ветки или тега.Используется если вы хотите вернуться к конкретной предыдущей версии файла, сохранив свои текущие правки в рабочей директории.

git revert создаёт новый коммит, который инвертирует (отменяет) изменения, внесённые указанным коммитом. Сам старый коммит остаётся в истории нетронутым. git reset --hard работает иначе: он перемещает указатель ветки (HEAD) на более ранний коммит, фактически «вычёркивая» из истории все коммиты после указанного. Если коммит уже был отправлен в общий (публичный) репозиторий и другие разработчики его получили через git pull, то попытка использовать git reset --hard (или reset в другом режиме, который переписывает историю) приведёт к проблемам.
